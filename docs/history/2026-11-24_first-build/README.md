# 2026-11-24 video_reader 첫 구축 — 요구 → 엔진 → 제품 화면 → 실제 영상 E2E

영상(유튜브·yt-dlp 가 여는 주소·이 PC 파일)을 넣으면 시각이 달린 구간별 정리를 내는 에이전트를 하루에 처음부터 만든 기록.
사용자는 방향만 주고 "이제 자율적으로 요구 사항에 맞는 에이전트 만들어봐"로 맡겼다. 콘셉트 고르기·평가 지적 분류는 사용자 확인 없이 추천안으로 진행했다.

## 무엇이 문제였나 → 어떻게 고쳤나

1. **상태 응답 9초** — 이 PC(WSL)는 닫힌 포트로 연결하면 거부 대신 시간 초과까지 기다렸다 (8002·8773 각 20초 측정).
   의존 확인을 연결 대기 1초 + 동시 확인으로 → 1.1초 (측정). `PROBE_TIMEOUT`.
2. **서버를 끄면 작업이 "취소됨"이 되고 stt 쪽 작업까지 취소** — 종료와 사람의 취소를 같은 신호로 처리했다.
   종료는 `Interrupted` → 줄로 되돌림, stt 작업은 그대로 두고 재시작 뒤 같은 messageId 로 이어 기다린다 (테스트 `test_restart_resumes_stt_without_resubmit`).
3. **"Claude Code가 그림을 읽지 못합니다"라는 거짓 문구** — Claude 가 화면 3장을 읽고 "더할 것 없음"이라 답한 구간(강연자 얼굴뿐)에 잠김 문구가 떴다.
   프레임마다 `read` 를 저장해 "읽었는데 더할 것 없음"과 "읽지 못함(잠김)"을 가른다.
4. **A2A 로 새로 들어온 일이 목록에 안 보임** — 진행 중 작업이 없으면 목록을 다시 받지 않았다 (browser_check 가 잡음). 한가할 때도 5초마다.
5. **요점 시각이 뒤섞임** (00:51 다음 00:24) — 프롬프트에 "그 내용이 처음 나온 줄의 [mm:ss], 앞 요점보다 작아지지 않는다" → 이후 실행에서 단조 증가.
6. **안내한 `VR_LOCAL_VISION=1` 이 실제로 연결돼 있지 않았음** — 화면 문구가 존재하지 않는 스위치를 안내했다. `default_engine` 이 환경 변수를 읽게 함.
7. **모델이 코드 줄바꿈을 `\n` 글자로 돌려줌** (Claude, 코드 슬라이드) → 엔진에서 실제 줄바꿈으로, 화면은 `pre-line`.
8. 화면 1회차 평가: 시각이 재생으로 이어지는지 정지 화면에서 안 보임 / 필름 띠 아래 빈 띠 / 구간 범위 대시가 마이너스처럼 / 내부 용어(A2A·stt 받아 적기) /
   `A · B` 메타 / 의존 상태 3줄이 운영 패널처럼 / 백엔드마다 문체가 다름(~한다 / ~함). 분류와 처리는 위 9·10단계.

## 남은 문제
- 로컬 LLM 으로 그림 읽기: 모델 설정에 `vision_config` 가 있지만 지금 띄우는 명령이 `image:0` 이라 미검증. 이미지를 켜면 8,192 컨텍스트에 그림 토큰이 들어가 구간 예산을 다시 봐야 한다.
- "필요할 때"의 화면 시각은 말에서 고른 시각이라, 슬라이드가 조금 늦게 뜨면 강연자 얼굴만 잡힌다 (TED 구간 2). 시각 뒤 몇 초를 더 보는 방법은 시험 안 함.
- 재생목록·여러 영상 한꺼번에(줄마다 하나는 됨)·번역 전용 출력·영상 파일 올리기(경로만 받음)는 없음.
- 화면: 셸(왼쪽 목록 + 회색 바탕 위 흰 판)이 stt 와 같은 틀로 읽힌다 (최종 평가 1 ⑪) — 콘셉트 카드에 부채로 적음. 390 폭에서 인화지가 먼저 나오지만 넣기 칸으로 돌아가는 길은 스크롤뿐.
  모든 시각 앞의 재생 표시를 최종 평가 2는 "반복 장식"으로 봤다 (1회차는 "재생으로 이어지는지 안 보임") — 사용자 판단 몫.
- 저장된 결과의 말투가 섞임(~니다 / ~다 / ~함): 프롬프트는 고쳤고(문장은 "~다") 다음 실행부터 적용. 개요와 가져갈 것의 겹침도 프롬프트만 고침 — 실제 실행으로 확인 안 함.
