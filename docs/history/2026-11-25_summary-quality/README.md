## 사용자 말
- "우선 우리 정리할 때도 어떤식으로 해야 좋은 정리글이 될지 등에 대해서 논의했던가?" → 논의한 적 없음 (11-24 자율 진행에서 혼자 정한 프롬프트)

## 바꾼 것
- 구성 먼저: 올린 사람 챕터 → 없으면 LLM 이 받아 적은 글을 2~3분 조각으로 읽으며 새 질문·항목·단계가 시작되는 줄을 찾음 → 못 찾으면 시간 (`engine.detect_structure`·`units_from_structure`)
- 구간: 제목(질문이면 질문 그대로) + 결론 한두 줄(gist) + 요점마다 역할(주장 claim / 근거 support / 설명 info)
- 글 층: 세 줄 결론(tldr) + 개요 + 가져갈 것(되풀이 금지), 쓰임새 공유 글이면 글 한 편 (`engine.article`)
- 쓰임새 4(기록·판단 기본 / 빠른 판단 / 공유 글 / 에이전트 입력)·중점 한 줄 — 화면·A2A(`purpose`·`focus`)·CLI. 묻지 않고 기본값으로 돈다
- 다시 쓰기 `POST /api/jobs/{id}/rewrite` — 글 층만 (테스트: 다시 쓰기 때 LLM 호출이 개요·공유 글 둘뿐)
- 예전 DB 에 칸을 더하는 이주

- 누락 검사: 원문의 숫자·영문·『』 제목이 정보 층에 다 있는지 스크립트로 세고(`key_tokens`·`coverage`), 빠지면 그 구간만 한 번 채움
