## 무엇이 문제였나와 원인

1. **정리 층이 영상 순서의 압축이었다.** 개요·구간별 한 줄 모두 "구간 → 한두 문장"이라, 여러 구간에 흩어진 같은 이야기(스피릿은 01:15·05:49·09:36에 나뉘어 나온다)가
   한 곳에 모이지 않았고, "세 가지 역량"처럼 이름만 나온 기준은 뜻이 없었다. 원인: 정리 층 지시가 "기록을 줄여 써라"였다 — 다시 세우라는 지시가 없었다.
2. **검토가 맞는 정의를 틀렸다고 고쳤다 (1단계).** "스피릿: '사내 창업자'·'조직 변화라는 긴 여정'은 원문 근거에 없음", "PO/PM: '인하우스 개발자와 준비 방법이 같다'는 원문 근거에 없음" —
   둘 다 원문에 있다 (09:51~10:45 "사내에서 스타트업을 창업한 것처럼", "조직은 절대 빨리 바뀌지 않는다" / 05:22 "앞서 말한 인하우스 개발자의 경우와 같다").
   원인: 검토에 준 근거가 "처음 나온 구간의 앞 몇 줄"뿐이라, 발췌 밖의 원문을 "없음"으로 판정했다. "PO / PM"은 앞 여섯 글자 "PO / P"로 찾아 한 자리도 못 찾았다.
3. **용어가 16개로 많고 군더더기가 섞였다** ("레슨런", "진입 장벽"), 목록 항목에 영상이 말하지 않은 뜻을 표시 없이 채웠다 ("부담감: 책임과 압박이다").
4. **만든 예시가 실제 일처럼 읽혔다** — "강사는 커리큘럼에 'API 연동과 배포…' 기준선을 적는다"는 "만든 예시" 표시가 있어도 실제 아카데미 이야기로 읽힌다.
5. **화면: 해석 상자 글자가 안 보였다.** 왼쪽 조작판 스타일이 `aside` 태그 전체에 걸려 있는데 해석 상자를 `aside`로 만들었다 (캡처를 보고 찾음).

## 어떻게 고쳤나

- 정리 층 단계를 **용어·기준 → 검토 → 예시 → 다시 짜기 → 세 줄 결론·구간별 한 줄** 순서로 (`engine.concepts`·`review_concepts`·`examples`·`restructure`).
  - 다시 짜기: 먼저 읽는 사람의 질문 3~6개를 세우고(낯선 대상이면 "그것이 무엇인가"가 첫 질문), 질문마다 영상 전체에서 답을 모아 엮는다. 주장에는 그가 든 이유·사례·숫자·비유를 붙인다.
    흩어진 내용을 잇는 해석은 `interpret`로 따로(두세 개까지), 예시는 앞 단계 것을 **번호로만** 가져와 "만든 예시" 표시가 글에서 떨어지지 않게 했다.
    근거로 한 번도 안 쓰인 구간은 `unused`로 남겨 빠뜨렸는지 볼 수 있게 했다.
  - Claude는 정보 층을 거의 통째로(12,000 토큰 예산), 로컬은 4,200.
- 검토 근거: 용어와 목록 항목 이름이 나온 **모든 자리**의 앞뒤 줄 + 제목에 그 용어가 든 구간 전체. 이름은 `/ · , ( )`로 나눠 찾는다. 지시도 바꿈 — "발췌에 없다는 이유만으로 틀렸다고 단정하지 않는다, 반대되는 내용이 있을 때만 고친다".
- 용어는 최대 8개, "이름만 나열돼 뜻을 알 수 없는 목록"은 꼭 넣고 누구나 아는 말은 뺀다. 목록 항목마다 `from_video`(영상에서 말한 뜻인가) — 아니면 "일반 뜻" 표시.
- 만든 예시: 말한 사람 본인이나 그 조직이 한 일처럼 쓰지 않는다, 일반적인 제3자 장면.
- 화면: 정리 탭 = 세 줄 결론 → 한 문단(바탕 판) → 번호 붙은 질문별 절(본문·목록·정리자 해석 띠·점선 예시 상자) → 용어와 기준 → 처지별로 해 볼 것 | 가져갈 것 → 구간별 한 줄(+예시).
  해석 상자는 `div role="note"`로.
- CLI·import 경로(`Engine.read`)도 같은 단계를 밟는다.

## 겹침 (7단계)

결과를 다시 읽으니 같은 것이 여러 번 나왔다. 원인과 고친 것:
- **세 역량을 용어 칸과 본문 절에서 두 번 항목별로 나열** — 두 단계가 각자 목록을 풀었다. 본문이 목록 항목을 다 풀었는지 코드로 판정해(`expanded_in_story`, 띄어쓰기 무시)
  용어 칸에는 정의만 두고 "항목별 뜻은 N절"로 가리킨다 (화면에서는 누르면 그 절로). 마크다운도 본문 → 용어 순서로 바꿔 "위 N절"이 맞게.
  처음에는 본문의 "파운더 스피릿"(띄어 씀)을 띄어쓰기를 지운 이름과 비교해 놓쳤다 — 양쪽 다 지우고 비교.
- **본문에 놓은 예시가 구간별 한 줄 아래 같은 글로 또 나옴** — 본문이 쓴 예시 번호를 `ex_used`로 남기고 구간별 한 줄에서는 뺀다. 같은 예시를 본문에 두 번 놓으면 두 번째는 버린다.
- **절 제목과 안 맞는 문단** ("쌓아 둘 경험" 절 끝에 "신입도 설계에 참여한다") — 절마다 `question`을 먼저 쓰게 하고 "그 질문에 답하는 것만, 다른 질문에 더 맞으면 옮긴다".
  4회차에서 "연차가 낮아도 FDE로 일할 수 있나?" 절이 따로 섰다.

## 남은 문제

- 세 줄 결론 · 한 문단은 본문의 결론을 짧게 다시 말한다 (요약이라 남김). 항목 나열 겹침은 7단계에서 없앰.
- 로컬 LLM 경로(예산 4,200)는 vLLM이 꺼져 있어 이번에 돌려 보지 않았다 — 켜면 다시 짜기가 8,192 안에 들어가는지 한 번 끝까지 돌린다.
- 시험 영상이 하나다. 성격이 다른 영상(강의·대담)에서 "질문을 먼저 세우기"가 맞는지는 확인 안 함.
- 정리 층 비용이 단계 넷이 늘어 전보다 커졌다 (전날 개요만 다시 만들 때 확인 안 함 → 이날 $0.55~0.63).
